# Agent Runtime 设计要点（知识库文档 AGENT-001）

本文档是本仓库 `read_docs` / `search` 工具的知识库素材之一，同时也说明 little-agent 的循环设计。

## 1. ReAct 循环

一个最小可用的 Agent Runtime 本质是一个受限的 while 循环：

```
观察（用户输入 + 工具结果） -> 思考（LLM） -> 行动（工具调用） -> 观察 -> ...
```

每一步 Runtime 必须回答三个问题：

1. 这一轮要交给模型什么上下文（context assembly）。
2. 模型的输出是「最终回答」还是「工具调用」（output parsing）。
3. 工具执行完之后是继续循环还是收尾（loop control）。

## 2. 循环终止条件

工程上循环必须有硬边界，否则会烧钱且可能死循环。little-agent 使用四个终止条件：

- 模型给出不含工具调用的最终回答（正常终止）。
- 达到最大迭代步数 `maxSteps`（默认 6），此时强制收尾。
- LLM 连续失败且重试耗尽（异常终止，返回可读错误）。
- 同一工具 + 同一参数被重复调用超过阈值（重复调用保护）。

## 3. 关键结论

- 循环控制权必须留在 Runtime，而不是交给模型：模型只能「请求」调用工具。
- 工具的返回值永远不要直接抛给用户，而是作为 observation 回灌给模型。
- 每一步都要落 trace，否则线上无法解释「Agent 为什么这样做」。
